# RCV Thoth

**Thoth** is a self-hosted contacts directory and calendar. One deployment works as a
**family address book**; turn on *work mode* and it becomes a **staff directory** your team
reaches from the company portal with Microsoft 365 single sign-on.

- **Home** — one search box, instant results, and a *Manage address book* button.
- **Address book** — full contact list with A–Z filter, groups, favorites, bulk select,
  **CSV / vCard import** (Google, Outlook and iCloud exports are recognised automatically)
  and **CSV / vCard export**.
- **Calendar** — month view with **birthdays and anniversaries from your contacts**, local
  events, and **subscribed external calendars** via any iCalendar (`.ics` / `webcal`) link.
  Publishes its own ICS feed, so Outlook, Google and Apple Calendar can subscribe back.
- **Portal** — a launcher page with tiles for the directory, calendar and any custom links.
- **Sign-in** — local accounts plus OpenID Connect SSO for **Microsoft Entra ID** and
  **Authentik** (any spec-compliant OIDC provider works in the Authentik slot). Directory
  groups map to admin / editor / viewer roles. Invitations, password resets and birthday
  digests go out over **SMTP**.
- **Sync to phones** — a **CardDAV** endpoint at `/dav`, so iOS, macOS and Android contacts
  apps subscribe to the directory with an app password.
- **Directory sync** — pull staff from **Microsoft 365** via Graph.
- **Org chart**, **custom fields**, contact **photos**, duplicate warnings, an **activity
  log** and one-click **database backup**.
- Themes: light, dark and hacker-green. No external fonts or CDNs.

Single container, SQLite database, no external services.

## Requirements

- **Docker** path (single host): Docker Engine + Docker Compose v2. Nothing else — the
  database is SQLite inside the container's data volume.
- **Kubernetes** path: Kubernetes 1.24+ and a `ReadWriteOnce` StorageClass.
- A DNS name for a public deploy. TLS is not optional but a certificate is: Thoth generates
  a self-signed one on first start if you do not supply one.

Published images are on GHCR under `ghcr.io/root-chain-ventures-llc/thoth`.

## Install with Docker Compose (single host — simplest)

```bash
git clone https://github.com/Root-Chain-Ventures-LLC/RCV-Thoth.git
cd RCV-Thoth
./install.sh
```

`install.sh` writes a `.env` with a strong random session secret and a random first-login
admin password that it prints **once**, pulls the published image, starts the container,
waits for health, and prints the URL.

Open it and sign in as that admin. If you would rather create the first account yourself,
clear `ADMIN_EMAIL` in `.env` — the first visit then shows a setup page.

- **Pin a release:** set `THOTH_VERSION=0.1.1` in `.env` (default `latest`).
- **Production:** set `BASE_URL=https://contacts.yourdomain` before the first start. SSO
  redirect URIs and the links in outgoing mail are built from it.
- To set configuration up front, copy `.env.example` to `.env` and edit it before running
  `./install.sh` — your values are preserved.

### Common `.env` keys

| Variable | Required | Notes |
|---|---|---|
| `THOTH_VERSION` | no | Image tag to pull (`latest`, or pin `0.1.1`). |
| `BASE_URL` | yes | Public `https://` URL. The server refuses to start on an `http://` one. |
| `SESSION_SECRET` | no | Cookie signing key. Auto-generated by `install.sh`; if unset the app generates one into the data volume. |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | no | Create the first administrator at startup instead of using the setup page. |
| `TLS_CERT`, `TLS_KEY` | no | PEM paths for your own certificate. Without them a self-signed pair is generated into the data volume. |
| `TLS_SELF_SIGNED_HOSTS` | no | Extra hostnames / IPs for that generated certificate. |
| `TRUST_PROXY` | no | `true` only behind a reverse proxy that terminates TLS and sets `X-Forwarded-Proto`. |
| `CALENDAR_SYNC_MINUTES` | no | Refresh interval for subscribed calendars (default 30). |

Everything else — branding, work mode, SSO, SMTP, roles, portal links — is configured in
**Settings** by an administrator and stored in the database. There are no environment
variables for those, by design.

## Install with Kubernetes

Manifests live in [`deploy/k8s/`](deploy/k8s/) — plain YAML, no Helm required.

```bash
kubectl create namespace thoth
kubectl -n thoth create secret generic thoth \
  --from-literal=SESSION_SECRET="$(openssl rand -hex 32)" \
  --from-literal=ADMIN_EMAIL=admin@example.com \
  --from-literal=ADMIN_PASSWORD="$(openssl rand -base64 24)"
kubectl apply -k deploy/k8s/
```

Edit `configmap.yaml` (`BASE_URL`), `ingress.yaml` (host, ingress class, certificate) and
`pvc.yaml` (size, StorageClass) first. [`deploy/k8s/README.md`](deploy/k8s/README.md) covers
the ingress choices and the rest of the detail.

**Do not raise `replicas`.** Thoth keeps the database, uploads, TLS material and session
secret in one SQLite file with a single writer, which is why the Deployment is one replica
with `strategy: Recreate` on a `ReadWriteOnce` volume.

## HTTPS

Thoth serves HTTPS itself and never serves a page in the clear. The same port answers plain
HTTP with a `301` to the `https://` URL — except `GET /api/health`, which answers `200` in
the clear so container and Kubernetes probes stay simple.

| Setup | What to do |
|---|---|
| Your own certificate | Set `TLS_CERT` and `TLS_KEY` to PEM files and mount them into the container. |
| Reverse proxy terminating TLS | Set `TRUST_PROXY=true` and `BASE_URL=https://…`. Requests that were not HTTPS at the edge are redirected. Only enable this behind a proxy, since it trusts the forwarded protocol. |
| Nothing configured | A self-signed certificate covering `localhost`, `127.0.0.1`, the `BASE_URL` host and any `TLS_SELF_SIGNED_HOSTS` is generated into the data volume and reused until 30 days before it expires. Traffic is encrypted; browsers warn once. |

HSTS is on for a year, cookies are `Secure`, and `BASE_URL` must be `https://`. There is a
plain-HTTP escape hatch (`ALLOW_INSECURE_HTTP=true`) intended for local development only —
it turns off every one of those protections and must never be set on a deployment.

## Single sign-on

Both providers use OpenID Connect with PKCE. Configure them under **Settings → Sign-in &
SSO**; the page shows the exact callback URI to register.

**Microsoft 365 / Entra ID**

1. Azure portal → Microsoft Entra ID → App registrations → *New registration*.
2. Redirect URI (Web): `https://<your-host>/api/auth/oidc/microsoft/callback`
3. Certificates & secrets → new client secret.
4. In Thoth enter the **tenant ID** (Directory ID), client ID and secret. The issuer is
   derived from the tenant, so you only copy what the portal shows.
5. For role mapping: Token configuration → *Add groups claim* → **Security groups**, ID format.

**Authentik (or any OIDC provider)**

1. Create an OAuth2/OpenID provider (confidential client) with redirect URI
   `https://<your-host>/api/auth/oidc/authentik/callback`, then an application using it.
2. In Thoth enter the issuer `https://<host>/application/o/<application-slug>/`, the client
   ID and the secret.

**Roles from directory groups.** Each provider has a *Role mapping* section: paste the group
object IDs (Entra) or group names (Authentik) that grant **admin**, **operator/editor** or
**viewer**. Admin wins over editor, editor over viewer, and anyone without a listed group
falls back to the default role. Roles are re-applied on every sign-in, so moving someone
between groups takes effect the next time they sign in — including demotions. This only
happens once at least one of the three fields is filled; leave all three empty and roles you
set by hand under **Users** stay put. The last enabled admin always keeps the role, so a
wrong group ID cannot lock everyone out of settings.

## Update

- **Docker:** bump `THOTH_VERSION` in `.env`, then `docker compose pull && docker compose up -d`.
- **Kubernetes:** bump the image tag in `deploy/k8s/deployment.yaml` and re-apply.

Database migrations run automatically at startup. Take a backup first — **Settings →
Maintenance → Download database backup**.

The running version is shown under **Settings → Maintenance → About this instance**; a
release image reports its version, commit and build time.

---

## Backup and restore

The data volume (`/data` in the container) holds everything: the SQLite database, uploaded
logos and contact photos, the TLS material and the generated session secret.

- **Database only:** Settings → Maintenance → *Download database backup* takes a consistent
  snapshot while the app is running.
- **Everything:** stop the container and copy the volume.
- **Restore:** stop the app, put `thoth.sqlite` back in the data directory, start it again.

## Uninstall

- **Docker:** `docker compose down` (add `-v` to also delete the data volume).
- **Kubernetes:** `kubectl delete -k deploy/k8s/` — the PersistentVolumeClaim goes with it,
  so snapshot the volume first if you want to keep the data.
